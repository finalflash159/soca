# Controlled workflow gate — 2026-07-30

## Decision

The controlled workflow is ready for the next integration block behind its
existing opt-in mode. Remote semantic behavior is the release signal. Local
models are wiring/resource smoke only and do not decide workflow quality.

The production invariants exercised here are:

- one typed terminal event per run;
- a public update is non-terminal and is followed by a scheduled action;
- declared source requirements produce a matching catalog action;
- tool/model/action budgets are accounted centrally;
- no retry occurs unless a failure is explicitly typed as transient;
- an empty retrieval terminates as `insufficient_evidence`;
- unexpected tool faults terminate as `system_failure`;
- no undeclared tool or capability is admitted by the planner schema.

## Scope boundary

This gate validates bounded goal/planning/execution control. It does not claim
that raw retrieval snippets are the final RAG answer architecture. Grounded
LLM synthesis, retrieval repair, citation faithfulness, capability-router
calibration, persistence, and production cutover remain in their dedicated
integration blocks.
