## Design Context

### Users

Vietnamese knowledge workers who use Sơn Ca as a local-first research and voice
assistant during focused desktop work. Their primary jobs are to ask grounded
questions, continue a prior line of work safely, and understand exactly when
their conversation remains only in memory versus is retained on their machine.

### Brand Personality

Calm, precise, and trustworthy. Product language is concise conversational
Vietnamese: it explains privacy, background work, and failure plainly rather
than making capability claims the runtime cannot prove.

### Aesthetic Direction

Preserve the existing content-first Sơn Ca visual system: restrained dawn-gold
accent, warm neutral light theme, iron-dark theme, Geist Variable typography,
and gently rounded surfaces. The workspace should make a long transcript easy
to read and session changes easy to verify. Avoid a rebrand, dashboard-card
clutter, decorative gradients, hover-only affordances, and motion that implies
activity when the engine is idle.

### Implementation Defaults

Detected existing stack takes precedence: React 19 + TypeScript + Vite in a
Tauri v2 desktop shell; Tailwind CSS v4 with CSS variables; shadcn base-nova
components and Base UI primitives; Lucide icons. The codebase has custom local
components composed over those primitives, not a new form, table, or
virtualization library. Treat it as Base-UI-flavoured and preserve the existing
composition and Vitest test stack. No framework fallback defaults are in use.

### Design Principles

1. Keep the transcript and the currently effective session unmistakable; do
   not update session UI before the engine confirms the operation.
2. Establish hierarchy with spacing, type, and grouping before using colour;
   reserve semantic colour for genuine state and pair it with words.
3. Make privacy and irreversible actions explicit: persistence is opt-in and
   delete names its consequence before it runs.
4. Give keyboard and assistive-technology users the same complete path as
   pointer users, including focus restoration and live status.
5. Prefer calm, truthful loading and error states to simulated progress or
   optimistic success.
